01 Executive Summary & Verdict

This specification defines the end-to-end build of a centralised digital marketing hub for a tech company, consolidating five social channels (Facebook, LinkedIn, TikTok, YouTube, Instagram) and a WhatsApp warm-lead channel into a single operational platform. The system's three pillars are process automation, cross-channel analytics, and AI-driven intelligence.

Recommended Architecture Decision

Hybrid: n8n for workflow orchestration + LangGraph for autonomous AI agents

Use n8n as the integration backbone — it handles scheduling, API calls, data pipelines, and deterministic workflows with zero code. Deploy LangGraph agents for tasks that require reasoning, multi-step decision-making, or adaptive behaviour: content scoring, lead classification, WhatsApp conversation management, and anomaly-triggered insight generation. The two layers communicate over HTTP/webhooks. This gives you the speed of a no-code platform where processes are predictable, and the intelligence of a custom agent framework where they are not.

02 Business Context & Goals

Problem statement

The marketing function currently operates each social channel in isolation. Content is created and published ad hoc, performance data lives in platform-native dashboards, no unified audience profile exists, and the WhatsApp channel (if in use) is manually managed. This creates duplicated effort, no cross-channel attribution, and no feedback loop from performance data back to content strategy.

Strategic objectives

P1 — Process Automation
  • Automate content scheduling and cross-posting across all 5 social channels
  • Automate lead capture from social DMs, comments, and link clicks into CRM
  • Automate WhatsApp broadcast sequences for warm leads (product updates, nurture flows)
  • Automate weekly/monthly performance report generation and distribution
P2 — Analytics & Intelligence
  • Unified cross-channel dashboard: reach, engagement, conversion, cost-per-lead
  • Audience segmentation by channel behaviour and lifecycle stage
  • Content performance scoring — what types, formats, and topics drive results
  • WhatsApp conversation analytics: response rates, drop-offs, conversion events
P3 — AI-driven Decisions
  • AI content brief generation based on trending topics + past performance data
  • Intelligent lead scoring and routing (cold → warm → WhatsApp nurture → sales)
  • Automated sentiment and intent classification on WhatsApp messages
  • Anomaly detection: flag underperforming campaigns in real time

Success metrics

Reduction in manual hours per campaign week (target: >60%), unified lead pipeline visibility, cost-per-acquisition tracked across all channels, WhatsApp engagement rate, AI content brief adoption rate by the creative team.

04 Platform Decision: n8n vs LangChain/LangGraph

This is the most critical architectural decision. The answer depends on clearly separating deterministic workflows (where the steps are known in advance) from agentic tasks (where the system must reason and decide). These are different problems that need different tools.

n8n

✓ Recommended for automation
Learning curveLow — visual
Setup speedDays, not weeks
API integrations500+ built-in nodes
Self-hostableYes (Docker)
CostFree OSS / low cloud
AI reasoningLimited (LLM node only)
Complex agent logicNot designed for it
Best forScheduling, ETL, API chains, triggers, notifications, reporting pipelines

LangChain + LangGraph

✓ Recommended for agents
Learning curveHigh — Python required
Setup speedWeeks
API integrationsManual (tool definitions)
Self-hostableYes
CostDev time + LLM API costs
AI reasoningNative, graph-based
Complex agent logicPurpose-built for it
Best forLead scoring, WhatsApp conversations, content analysis, multi-step reasoning

Decision rationale: Use both, with clear boundaries

Neither tool alone is sufficient. n8n alone cannot support the intelligent decision-making required for lead classification or conversational WhatsApp flows. LangGraph alone cannot manage the 50+ deterministic integration tasks (scheduling posts, pulling API metrics, sending reports) without excessive custom code. The hybrid approach means: n8n owns the plumbing (triggers, data movement, notifications), and LangGraph agents are callable services that n8n invokes via HTTP when intelligence is needed. This is the industry-standard pattern for production AI automation.

05 Recommended System Architecture

The hub is structured as five logical layers, each with a clear responsibility. Data flows upward from channels to intelligence, and decisions flow back downward to channel actions.

Layer 1 — Channel Ingestion

Webhook listeners and scheduled API pollers that collect raw data (posts, engagement metrics, DMs, comments, new followers) from each platform. Built in n8n. Each channel has its own ingestion workflow to isolate failures.

Channels
  • Facebook/Instagram — Meta Graph API (posts, insights, messenger webhooks)
  • LinkedIn — LinkedIn Marketing API (organic + paid, follower analytics)
  • TikTok — TikTok for Business API (video metrics, profile data)
  • YouTube — YouTube Data API v3 (video performance, comments, subscribers)
  • WhatsApp — WhatsApp Business API via Meta (Cloud API or BSP like 360Dialog / Twilio)
n8n nodes: HTTP Request, Webhook, Schedule Trigger, Meta node, YouTube node

Layer 2 — Central Data Store

All ingested data is normalised and stored in a single schema. This is the single source of truth for analytics, agent context, and reporting. The unified schema maps to DICM-450 (Data/Warehouse Stores).

Data store schema (key tables)
  • channels — platform, account, connected status
  • posts — content, channel, publish time, format, topic tags
  • post_metrics — impressions, reach, engagements, clicks, video views (daily)
  • leads — source channel, contact info, stage, score, assigned_to
  • whatsapp_conversations — thread_id, messages, timestamps, classification, outcome
  • campaigns — name, objective, budget, start/end, channels, KPIs
  • content_briefs — AI-generated brief, topic, format, target channel, status
PostgreSQL (self-hosted) or BigQuery (cloud). Redis for caching hot metrics.

Layer 3 — Automation Engine (n8n)

n8n is the operational backbone. It runs on a schedule or reacts to webhooks and executes deterministic pipelines. It also calls out to LangGraph agents when AI processing is needed.

Layer 4 — Intelligence Layer (LangGraph)

A Python FastAPI service hosting LangGraph agent graphs. Each agent is a stateful graph with nodes for LLM calls, tool use, memory retrieval, and conditional routing. Agents are invoked by n8n via POST requests and return structured JSON.

Layer 5 — Dashboard & Control Plane

A web frontend (Next.js or Metabase) that provides the unified analytics view, content calendar, lead pipeline, and WhatsApp broadcast management. Non-technical users operate the hub from this layer.

06 Module Specifications

Module A: Channel Publishing Engine

Purpose
  • Content calendar: schedule posts for one or all channels from a single interface
  • Cross-post with channel-specific formatting (caption length, hashtags, aspect ratios)
  • Queue management: drafts, scheduled, published, failed states
  • Support for post types: image, video, carousel, link, story (where API allows)
n8n Schedule Trigger → format transformation → Meta/LinkedIn/TikTok/YouTube API nodes

Module B: Analytics Dashboard

Purpose
  • Cross-channel KPI summary: total reach, total engagements, total leads, CPL
  • Channel-by-channel breakdown with benchmarks (DICM-1878)
  • Content performance: top/bottom performing posts by format, topic, channel
  • Audience growth over time, follower quality indicators
  • Campaign attribution: which channel drove which lead conversion
  • Automated weekly PDF report emailed to stakeholders (n8n + PDF generation)
n8n nightly ETL → PostgreSQL → Metabase (self-hosted) OR Next.js + Chart.js/Recharts

Module C: AI Content Brief Generator (LangGraph Agent)

Agent graph
  • Node 1 — Context retrieval: fetch top 10 performing posts (last 30 days) from DB + current trending topics via web search tool
  • Node 2 — Pattern analysis: LLM identifies winning content patterns (format, hook style, topic clusters)
  • Node 3 — Brief generation: outputs structured brief (topic, hook, format, channel, CTA, estimated performance band)
  • Node 4 — Storage: writes brief to content_briefs table, notifies creative team via Slack/email
LangGraph + Claude/GPT-4o + PostgreSQL tool + Brave Search tool · Triggered by n8n on Monday mornings or on-demand from dashboard

Module D: Lead Capture & Scoring Engine

Purpose
  • Capture leads from: social link clicks (UTM-tracked), DM responses, comment interactions, WhatsApp opt-ins
  • Enrich contact: name, channel source, content interaction history, engagement frequency
  • LangGraph scoring agent: classifies each lead as cold/warm/hot based on behaviour signals
  • Routing: warm/hot leads → WhatsApp nurture; cold leads → retargeting audience
  • CRM sync: push qualified leads to HubSpot/Pipedrive/Salesforce via API (DICM-731)
n8n webhook → LangGraph scoring agent → CRM node → WhatsApp trigger workflow

Module E: WhatsApp Hub (Warm Lead Nurture)

Purpose
  • Opt-in management: double opt-in flow compliant with WhatsApp Business Policy and GDPR (DICM-1854)
  • Broadcast sequences: templated message sequences triggered by lead stage (new, engaged, product-interest, dormant re-engagement)
  • Message personalisation: first name, product interest, last interaction reference
  • Conversational agent: LangGraph agent handles inbound replies — classifies intent, routes to human agent if needed, or auto-responds with relevant product info
  • Analytics: open rate (read receipts), reply rate, conversion events (link click, booking, purchase)
WhatsApp Cloud API (Meta) or 360Dialog BSP → n8n for broadcast scheduling → LangGraph conversational agent for inbound

Module F: Anomaly Detection & Alerts

Purpose
  • n8n monitors daily metrics against rolling 14-day baseline
  • Flags: sudden reach drop (>30%), engagement rate collapse, unusually high negative comments, follower spike (bought followers indicator)
  • Anomaly passed to LangGraph agent which generates a plain-English diagnostic and recommended action
  • Alert delivered to Slack channel + dashboard notification
n8n Schedule Trigger → threshold evaluation → conditional: if anomaly → LangGraph diagnostic agent → Slack node

08 Implementation Roadmap

A four-phase delivery over approximately 16 weeks, sequenced to deliver value early and add intelligence incrementally.

Foundation — Ingestion & Data Store

Weeks 1–3 · Backend developer + n8n administrator
  • Provision infrastructure (Docker, Postgres, n8n, Redis)
  • Register developer apps on Meta, LinkedIn, TikTok, YouTube; complete OAuth flows
  • Build n8n ingestion workflows per channel (nightly metric pulls)
  • Design and migrate database schema (posts, metrics, leads, conversations)
  • Basic n8n dashboard: workflow health, last run status
  • WhatsApp Business API account setup and message template approval

Automation — Publishing & Lead Capture

Weeks 4–7 · n8n admin + frontend developer
  • Content calendar UI: create/schedule posts, assign to channels
  • n8n publishing workflows per channel with formatting transformations
  • UTM parameter injection on all outbound links
  • Lead capture webhooks from social link clicks and form fills
  • WhatsApp opt-in flow: broadcast list building with double opt-in
  • First WhatsApp broadcast sequence (welcome + product intro, 3-message drip)
  • CRM sync for captured leads

Analytics — Unified Dashboard & Reporting

Weeks 8–11 · Analytics developer + frontend
  • Metabase or custom dashboard: cross-channel KPI overview
  • Channel breakdown views, content performance table
  • Audience growth charts, follower quality tracking
  • Campaign attribution model (last-touch, first-touch)
  • Automated weekly PDF report workflow in n8n
  • WhatsApp analytics: open rate, reply rate, conversion tracking
  • Anomaly detection workflows with Slack alerts

Intelligence — AI Agents

Weeks 12–16 · Python/AI developer
  • Deploy FastAPI agent service (Docker)
  • Build and test LangGraph lead scoring agent
  • Build and test content brief generator agent (with web search tool)
  • Build WhatsApp conversational agent (intent classification + FAQ response + human handoff)
  • Build anomaly diagnostic agent (called from n8n on threshold breach)
  • Wire all agents into n8n workflows via HTTP Request nodes
  • Agent evaluation: measure scoring accuracy, brief adoption rate
  • Stakeholder training and documentation handover

09 Risks & Mitigations

RiskLikelihoodImpactMitigation
Meta API rate limits throttle ingestion during campaigns Medium Medium Implement exponential backoff in n8n, cache last-known values, stagger polling windows per channel
WhatsApp template rejections delay broadcast launch High Medium Submit templates 10+ business days before launch; prepare multiple variants; use pre-approved utility templates initially
LLM hallucination in content briefs sent to creative team Medium Low Frame briefs as suggestions not directives; add human approval step before brief is marked active; log all AI outputs
GDPR/data compliance for WhatsApp contact storage Medium High Double opt-in, explicit consent records, easy unsubscribe in every message, data stored in compliant region (DICM-1854)
LinkedIn API access restricted to approved partners Low Medium Apply for Marketing Developer Platform access early; use native analytics export as interim fallback
LangGraph agent latency makes WhatsApp responses slow Medium Medium Send immediate acknowledgement message ("We're looking into that…") while agent processes; target sub-5s agent response time; cache common FAQ responses
n8n workflow sprawl becomes unmanageable over time Medium Low Enforce naming conventions, folder structure, and tagging from day one; document each workflow's purpose in its description field; quarterly audit

10 Appendix: API & Integration Notes

Meta (Facebook + Instagram)

Use the Meta Graph API v19+. Publishing requires a Facebook Page (not personal profile). Instagram publishing requires a Professional account linked to a Facebook Page. Metrics available: impressions, reach, engagement, clicks, saves, profile visits. Webhooks available for new comments and messages. Rate limit: 200 calls/hour per user token.

LinkedIn

Requires the Marketing Developer Platform partnership for full advertising and analytics access. For organic content only, the basic API allows post creation and basic engagement metrics. Apply at linkedin.com/partners. Follower analytics and detailed post insights require r_organization_social scope.

TikTok

The TikTok for Business API covers both organic (Content Posting API) and paid (Ads API). Video upload requires a two-step flow: initiate upload → upload chunks → publish. Organic insights (views, likes, shares, comments, watch time) available via the Research API. Apply via ads.tiktok.com/marketing_api.

YouTube

YouTube Data API v3 is freely available via Google Cloud Console. Quota: 10,000 units/day (sufficient for nightly pulls). Video statistics, channel stats, comments, and captions all accessible. Live broadcast management available if needed.

WhatsApp Business API

Two options: WhatsApp Cloud API (direct Meta, free per-message pricing) or a Business Solution Provider like 360Dialog, Twilio, or Bird. Cloud API is recommended for cost control. All broadcast messages must use pre-approved templates. Conversational (session) messages are free within a 24-hour window. Minimum phone number requirement: a verified business phone number (can be a VoIP number).

n8n ↔ LangGraph communication

LangGraph agents are deployed as a FastAPI service. Each agent is exposed as a POST endpoint (e.g., POST /agents/score-lead, POST /agents/generate-brief). n8n calls these via the HTTP Request node, passing structured JSON payloads and receiving structured JSON responses. Authenticate with a shared API key stored in n8n credentials vault.
