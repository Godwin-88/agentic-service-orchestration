01

Executive Summary

The Digital Marketing Hub (v1.0) delivers channel automation, cross-platform analytics, and AI-driven content intelligence. Its lead capture module (Module D) seeds a contact store and routes warm leads to WhatsApp — but stops there. No persistent contact profiles are maintained, no lifecycle stage transitions are governed, no deal pipeline exists, and no autonomous follow-up occurs beyond the initial WhatsApp broadcast.

This specification defines an Agentic CRM layer that augments the hub with a full customer relationship lifecycle — from first social signal through opportunity management, proposal generation, and post-sale retention — driven by autonomous AI agents embedded within the same n8n + LangGraph infrastructure the hub already operates.

Architecture decision: The CRM is not a separate product. It is a set of new database tables, new LangGraph agent graphs, and new n8n workflow branches that share the hub's existing PostgreSQL store, FastAPI agent runtime, and channel integrations. No new infrastructure category is introduced. Estimated incremental build: 10–12 weeks on top of the hub's existing 16-week foundation.

Three pillars of the Agentic CRM

  • Unified Contact & Account Lifecycle — persistent profiles enriched from every channel interaction, with autonomous stage progression governed by agent-evaluated signals.
  • Autonomous Sales Orchestration — opportunity management, proposal drafting, and follow-up sequencing handled by agents without manual triggering.
  • Retention & Loyalty Intelligence — churn prediction, re-engagement sequencing, RFM segmentation, and sentiment-driven intervention — all running continuously in the background.

Business Context & CRM Problem Statement

Gap in the current hub

The hub's Module D captures leads and scores them (cold / warm / hot), then either routes warm leads into a WhatsApp broadcast sequence or drops cold leads into a retargeting audience. After that handoff the hub has no further visibility into what happens. There is no:

  • Persistent contact record accumulating interaction history across sessions
  • Lifecycle stage model governing how a contact progresses from prospect to customer to advocate
  • Deal or opportunity pipeline with stage, value, and probability
  • Autonomous follow-up when a lead goes cold inside the WhatsApp conversation
  • Post-sale account management or retention logic
  • RFM (Recency / Frequency / Monetary) segmentation feeding back into campaign targeting

Strategic objectives

  • SO-1 — Close the loop: every lead the hub generates must have a governed lifecycle path, not just a first touchpoint.
  • SO-2 — Reduce human triage burden: agents autonomously qualify, follow up, propose, and escalate — humans intervene only at defined decision gates.
  • SO-3 — Feed intelligence back: CRM outcomes (won deals, churn events, NPS responses) flow back into the hub's analytics and content brief generation, closing the marketing-to-revenue loop.
  • SO-4 — Canvas alignment: every CRM capability is traceable to a DICM capability ID so the build remains inside the enterprise EA framework.

Success metrics

  • Lead-to-opportunity conversion rate (baseline vs. post-CRM)
  • Average days from first contact to first proposal (target: <5 days, automated)
  • Churn rate on qualified accounts (target: 15% reduction within 6 months)
  • Agent-handled follow-ups vs. human-handled (target: >70% agent-autonomous)
  • RFM segment accuracy: verified by quarterly cohort analysis

Augmentation Architecture — How CRM Fits the Hub

The CRM does not introduce a separate system. It extends all five hub layers with new tables, new agent graphs, and new workflow branches. The boundary between hub and CRM is a handoff event: when the hub's scoring agent classifies a lead as warm or hot, ownership transfers from the hub's lead capture pipeline to the CRM's contact intelligence engine.

Data flow overview

Hub LayerCRM ExtensionTrigger
Layer 1 — Channel Ingestion Social interaction events (comments, DM replies, link clicks) tagged with contact_id after first match to CRM contact record n8n webhook enrichment node, post-ingestion
Layer 2 — Central Data Store New tables: contacts, accounts, lifecycle_events, opportunities, proposals, retention_signals, rfm_scores Schema migration at CRM Phase 1
Layer 3 — Automation Engine (n8n) New workflows: lifecycle stage watcher, follow-up scheduler, proposal trigger, churn alert dispatcher Cron + webhook + event-driven from CRM tables
Layer 4 — Intelligence Layer (LangGraph) New agents: Contact Profile Agent, Opportunity Qualification Agent, Proposal Drafting Agent, Retention Intervention Agent Called by n8n via POST /agents/crm/* endpoints
Layer 5 — Dashboard New CRM views: contact timeline, pipeline board, retention heatmap, RFM quadrant chart, revenue forecast Metabase dashboards or Next.js CRM panel

Handoff protocol (Hub → CRM)

When POST /agents/score-lead returns score: warm | hot, n8n fires a crm.lead.qualified internal event. This triggers the CRM's Contact Profile Agent (POST /agents/crm/build-contact), which creates or merges a contacts record and begins lifecycle tracking. The original leads record is retained for attribution but is no longer the system of record — the contacts table takes over.

Module Specifications

The CRM adds five modules (G through K) to the hub's existing A–F modules. Each is designed to operate autonomously with a human approval gate at defined escalation points only.

Module G: Contact Intelligence Engine

Canvas: DICM-731, DICM-720, DICM-1875, DICM-640

The hub creates raw leads. The Contact Intelligence Engine transforms them into persistent, enriched contact profiles and maintains those profiles over the full relationship lifecycle.

Responsibilities

  • Create a canonical contacts record on first qualification, deduplicating against email, phone, and social handle
  • Merge interaction history from all hub channels (social engagements, WhatsApp threads, link clicks) into the contact timeline
  • Enrich contact with firmographic data via Clearbit / Apollo API (company, role, industry, company size)
  • Maintain lifecycle stage: prospect → qualified → engaged → opportunity → customer → advocate
  • Compute and update a contact health score (0–100) based on recency, engagement depth, and channel breadth
  • Detect and flag contact inactivity thresholds (configurable: default 7 days no interaction = flag for follow-up)
  • Sync two-way with CRM of record (HubSpot / Pipedrive / Salesforce) via n8n nodes

n8n workflows

  • crm-contact-create — triggered by crm.lead.qualified event
  • crm-contact-enrich — nightly batch: call Clearbit/Apollo for contacts with missing firmographic data
  • crm-contact-health-recalculate — hourly: recalculate health scores based on new interactions
  • crm-contact-sync — bidirectional CRM sync every 15 minutes

Module H: Opportunity & Pipeline Manager

Canvas: DICM-386, DICM-770, DICM-3466, DICM-1680

Manages the commercial pipeline from first qualified opportunity through proposal, negotiation, and close — with autonomous agents handling qualification assessment and proposal generation.

Responsibilities

  • Create opportunity records when a contact's health score crosses a configurable threshold or a WhatsApp conversation signals purchase intent
  • Manage pipeline stages: identified → qualified → proposal_sent → negotiation → closed_won | closed_lost
  • Store deal value, probability, expected close date, and assigned owner per opportunity
  • Autonomous opportunity qualification: agent evaluates contact profile, firmographic data, and conversation history to score qualification (BANT: Budget, Authority, Need, Timeline)
  • Proposal drafting: agent generates a structured proposal draft populated with company-specific data, product offering, and pricing — subject to human review before send
  • Conversion incentive logic: when opportunity is stalled at proposal_sent for >3 days, agent proposes an incentive (discount, free trial, POC) from a configured catalogue
  • Pipeline analytics: velocity, win rate, average deal value, stage conversion funnel

Human gates

  • Proposal review: drafted proposal queued in dashboard, must be approved (or edited) before send
  • Incentive approval: agent recommends incentive, sales manager approves via Slack button or dashboard
  • Deal closure: closed_won transitions require human confirmation

Module I: Autonomous Follow-Up Engine

Canvas: DICM-788, DICM-697, DICM-737, DICM-773, DICM-806

Eliminates manual follow-up triage. The engine monitors all open contacts and opportunities, determines the next best action, and autonomously executes or queues that action.

Responsibilities

  • Next Best Action (NBA) agent: for each contact with a due follow-up, the agent evaluates contact history, stage, last interaction channel, and content consumed — then determines the optimal follow-up: WhatsApp message, email, social comment reply, or human call flag
  • Sequences follow-ups across channels without channel overlap in the same 24-hour window
  • Assigns cases when an inbound message requires response: routes to the NBA agent first; if the agent determines human handling is needed, creates a task assigned to the relevant team member with full context
  • Tracks case status (open → in_progress → resolved) and sends SLA alerts at configurable thresholds (e.g. 4 hours unresolved = Slack alert)
  • Logs all autonomous actions with reasoning traces for audit and quality review

Channel priority logic (configurable)

  1. WhatsApp (if contact has active session within 24-hour window)
  2. Email (if firmographic enrichment has corporate email)
  3. Social DM on originating platform
  4. Human call flag (if 3+ autonomous touchpoints with no response)

Module J: Retention & Loyalty Agent

Canvas: DICM-648, DICM-681, DICM-712, DICM-637, DICM-449, DICM-696, DICM-656, DICM-787

Operates on the existing customer base (contacts in customer or advocate stage) to reduce churn, increase lifetime value, and generate referrals.

Responsibilities

  • RFM Segmentation: weekly recalculation of Recency, Frequency, Monetary scores for all customers; segments: Champions, Loyal, At-Risk, Hibernating, Lost. Results feed back to hub's audience targeting
  • Churn prediction: LangGraph agent evaluates engagement decline patterns, NPS drop signals, support ticket frequency, and payment latency to produce a churn probability score per account
  • Re-engagement sequencing: for At-Risk and Hibernating segments, agent autonomously launches a personalised re-engagement WhatsApp or email sequence (distinct from marketing broadcasts)
  • Sentiment monitoring: agent analyses WhatsApp conversations and social mentions for brand sentiment shifts; flags negative sentiment for human review and triggers empathetic outreach
  • NPS & survey orchestration: sends NPS surveys at configurable intervals (post-onboarding, 90-day, 1-year); aggregates scores into retention dashboard
  • Advocacy identification: contacts with NPS ≥ 9 and 3+ referral actions flagged as advocates; agent triggers advocacy program invitation

Module K: CRM Analytics & Revenue Dashboard

Canvas: DICM-1873, DICM-1590, DICM-820 (shared with hub)

Extends the hub's analytics dashboard with CRM-specific views that close the marketing-to-revenue loop — feeding outcome data back into the hub's content and campaign intelligence.

Views & metrics

  • Pipeline board: Kanban-style opportunity view by stage, value, and probability
  • Revenue forecast: weighted pipeline value by expected close date (30/60/90-day buckets)
  • Contact lifecycle funnel: conversion rates at each stage, average time-in-stage, bottleneck identification
  • RFM quadrant chart: visual segmentation of customer base
  • Retention heatmap: churn probability by account cohort and segment
  • Attribution bridge: maps won opportunities back to originating marketing channel and content piece — closing the loop between Module B (hub analytics) and CRM outcomes
  • Agent activity log: all autonomous actions, decisions, and reasoning traces, reviewable by managers

Agentic Design — Agent Graphs & Decision Logic

Each CRM agent is a LangGraph stateful graph deployed within the existing FastAPI agent service at http://agents:8000. Agents persist state across invocations using the CRM's lifecycle_events table as long-term memory.

Agent G1: Contact Profile Builder — POST /agents/crm/build-contact

  • Dedup check — query contacts table by email + phone + social handles; merge if match found
  • Firmographic enrichment — call Clearbit/Apollo with email domain; store company, role, industry, headcount
  • Interaction aggregation — pull all hub lead events (source channel, content touched, WhatsApp thread ID) and write to contact timeline
  • Health score calculation — LLM evaluates recency, channel breadth, interaction depth; outputs score 0–100 with rationale
  • Lifecycle stage assignment — conditional routing: qualified → engaged (if health ≥ 60); stays prospect (if < 60)
  • CRM sync — upsert to HubSpot/Pipedrive via REST; return contact_id to n8n workflow

Agent H1: Opportunity Qualification Agent — POST /agents/crm/qualify-opportunity

  • Context retrieval — fetch contact profile, conversation history (last 10 WhatsApp messages), firmographic data
  • BANT assessment — LLM evaluates Budget signals, Authority indicators, Need clarity, Timeline urgency from conversation history
  • Qualification decision — conditional: if BANT score ≥ threshold → create opportunity record; else → flag contact for nurture continuation
  • Opportunity record creation — write to opportunities table: estimated value, probability, expected close, qualification rationale
  • Assignment routing — based on deal size, route to appropriate sales owner; notify via Slack

Agent H2: Proposal Drafting Agent — POST /agents/crm/draft-proposal

  • Requirement extraction — LLM parses opportunity notes and conversation history to extract stated requirements and pain points
  • Product matching — tool call to product catalogue (DB query); matches requirements to offerings
  • Draft generation — LLM generates structured proposal (executive summary, solution fit, pricing, timeline, next steps) using company template
  • Quality check — self-critique node: LLM reviews draft for completeness, tone, and accuracy against requirements; revises if needed
  • Human review queue — writes proposal to proposals table with status pending_review; sends Slack notification with preview link

Agent I1: Next Best Action Agent — POST /agents/crm/next-best-action

  • Context load — fetch contact profile, full interaction history, open opportunity status, last follow-up timestamp and outcome
  • Action selection — LLM evaluates context and selects from: WhatsApp message, email, social engagement, incentive trigger, human escalation, or no-action (do not over-contact)
  • Message generation — if action requires outreach, LLM generates personalised message with reference to last interaction and specific value proposition
  • Channel gating — check last 24-hour channel activity to avoid double-touch on same channel; reroute if needed
  • Execution — invoke n8n webhook to send message or create human task; log action with reasoning trace to lifecycle_events

Agent J1: Retention Intervention Agent — POST /agents/crm/retention-check

  • Churn signal detection — evaluate engagement velocity decline, support ticket trend, payment status, NPS score change
  • Churn probability scoring — LLM outputs probability (0–1) with contributing factors
  • Intervention selection — conditional: High risk (≥0.7) → personalised re-engagement + flag for human; Medium (0.4–0.7) → automated sequence; Low (<0.4) → no action
  • Sequence generation — for automated interventions, generates 3-message re-engagement sequence tailored to customer segment and churn signal type
  • Outcome tracking — monitor re-engagement response rate; update churn probability after each response event; log results

Implementation Roadmap

The CRM build runs in parallel from hub Week 8 onward, completing in approximately 10–12 weeks after hub Phase 1 (data infrastructure) is live. Phases below are CRM-specific; hub phases are a prerequisite.

CRM Phase 1 — Data Foundation & Contact Engine

Weeks 1–3 (parallel with Hub Week 8–10)
  • Design and migrate CRM schema extensions (contacts, accounts, lifecycle_events, rfm_scores)
  • Build crm-contact-create n8n workflow; wire to hub's lead scoring handoff event
  • Deploy Agent G1 (Contact Profile Builder) to FastAPI service; test deduplication logic
  • Integrate Clearbit/Apollo enrichment API; build nightly enrichment workflow
  • Build bidirectional CRM sync workflow (HubSpot/Pipedrive) with conflict resolution rules
  • Basic contact list view in dashboard: lifecycle stage, health score, last interaction

CRM Phase 2 — Pipeline & Follow-Up Automation

Weeks 4–7
  • Deploy Agent H1 (Opportunity Qualification) and Agent I1 (Next Best Action)
  • Build opportunity and follow_up_actions table migrations
  • Build crm-opportunity-watcher n8n workflow (hourly health score evaluation → opportunity trigger)
  • Build crm-followup-scheduler n8n workflow (daily: identify contacts due for follow-up → call NBA agent)
  • Pipeline Kanban board in dashboard; deal stage drag-and-drop with human confirm gates
  • Slack notification templates for human gates (proposal review, escalation)
  • Agent reasoning trace viewer in dashboard (manager audit view)

CRM Phase 3 — Proposal Engine & Revenue Analytics

Weeks 7–9
  • Deploy Agent H2 (Proposal Drafting); build proposal template library in DB
  • Proposal PDF rendering pipeline (Pandoc or Puppeteer → S3/R2 storage)
  • Proposal review UI: preview, edit, approve/reject in dashboard
  • Build revenue forecast dashboard view (weighted pipeline, 30/60/90-day buckets)
  • Attribution bridge: link won opportunities back to originating campaign and content piece in hub analytics
  • Conversion incentive catalogue: configurable discount / trial / POC options per product line

CRM Phase 4 — Retention Intelligence & Full Loop Closure

Weeks 10–12
  • Deploy Agent J1 (Retention Intervention); build retention_signals and nps_responses tables
  • Build weekly RFM recalculation workflow (SQL-based, results stored in rfm_scores)
  • Wire RFM segments back to hub's audience targeting (feed into campaign segmentation)
  • NPS survey trigger workflow (WhatsApp survey flow or Typeform integration)
  • Retention heatmap and RFM quadrant dashboard views
  • Advocacy program trigger: flag NPS ≥ 9 contacts, send advocacy invitation sequence
  • End-to-end integration test: social signal → lead → contact → opportunity → proposal → won → retention loop
  • Stakeholder training, agent evaluation report (qualification accuracy, follow-up response rates), documentation handover

Risks & Mitigations

RiskLikelihoodImpactMitigation
Agent follow-up over-contacting a lead, causing opt-out High High Enforce channel gating rules (max 1 autonomous touchpoint per channel per 24h); global contact-frequency cap (configurable, default: 3 touches per 7 days); opt-out triggers immediate suppression in all CRM workflows
Contact deduplication failure creating ghost records in CRM Medium Medium Dedup on email AND phone AND social handle; confidence scoring for fuzzy matches — low-confidence merges queued for human review rather than auto-merged; weekly dedup audit report
Proposal agent hallucinating product specs or pricing Medium High Proposal is always in pending_review status until human approval; agent pulls product specs exclusively from the product catalogue DB tool (no free-text generation of specs); human reviewer has edit capability before send
Firmographic enrichment data outdated or inaccurate Medium Low Flag enrichment date on contact profile; re-enrich quarterly; allow manual override of any enriched field; do not use enriched headcount for deal value calculations without human confirmation
CRM of record sync conflicts (e.g. deal stage edited in HubSpot and in CRM simultaneously) Medium Medium Define CRM (this system) as master of record for agent-generated data; CRM of record (HubSpot) as master for human-edited data; conflict detection log with Slack alert on field-level conflict
Churn prediction false positives triggering unnecessary re-engagement for healthy accounts Medium Low Quarterly cohort calibration of churn model; A/B test re-engagement sequence against control group; opt accounts out of proactive sequences if NPS ≥ 9 and health score ≥ 80
Agent reasoning traces growing to unmanageable size in lifecycle_events table Low Low Archive lifecycle_events older than 180 days to cold storage (S3/R2); summarisation agent runs monthly to produce compressed contact narrative from raw events before archival
GDPR compliance gap: CRM stores personal data without sufficient consent basis Low High Inherit consent records from hub's DICM-1854 consent module; CRM contact creation blocked if no valid consent record; right-to-erasure workflow deletes contact from CRM, hub, and CRM of record; data stored in compliant region

Appendix: API & Integration Notes

Clearbit Enrichment API

Use Clearbit.enrich({email}) to fetch company and person data. Returns company name, domain, industry, headcount range, and LinkedIn URL. Rate limit: 1,200 requests/minute on paid plan. For batch nightly enrichment, use the Clearbit Streaming API to avoid hammering limits. Store raw response in contacts.enrichment_raw (JSONB) for auditability. Apollo.io is the recommended fallback: POST /v1/people/match with email returns similar firmographic payload at lower cost.

HubSpot / Pipedrive / Salesforce Sync

n8n has native nodes for all three. The sync strategy is event-driven upsert: on every lifecycle_events write, n8n fires the CRM sync workflow. Use the hs_object_id (HubSpot) or id (Pipedrive) stored in the contacts.external_crm_id column to avoid creating duplicate records. For Salesforce, use the SOAP API's upsert operation with Email as the external ID field.

n8n → LangGraph CRM Agent Endpoints

POST /agents/crm/build-contact       # Agent G1 — input: lead_id; output: contact_id, health_score, stage
POST /agents/crm/qualify-opportunity # Agent H1 — input: contact_id; output: qualified (bool), bant_score, rationale
POST /agents/crm/draft-proposal      # Agent H2 — input: opportunity_id; output: proposal_id, draft_content
POST /agents/crm/next-best-action    # Agent I1 — input: contact_id; output: action_type, channel, message, reasoning
POST /agents/crm/retention-check     # Agent J1 — input: contact_id; output: churn_probability, intervention_type, sequence

All endpoints accept and return structured JSON. Authenticate with the shared AGENT_API_KEY already configured in the hub's n8n credential vault. Add timeout: 30s on n8n HTTP Request nodes for CRM agents (proposal drafting may take longer than lead scoring).

Proposal PDF rendering

Agent H2 returns a structured JSON proposal (sections, content, pricing table). Render to PDF using Puppeteer (headless Chrome) or Pandoc with a Jinja2 HTML template. Upload to S3/Cloudflare R2 and store the public URL in proposals.pdf_url. The dashboard proposal review panel embeds the PDF via iframe.

RFM Calculation (SQL pattern)

-- Weekly job run by n8n
INSERT INTO rfm_scores (contact_id, recency_score, frequency_score, monetary_score, rfm_segment, calculated_at)
SELECT
  contact_id,
  NTILE(5) OVER (ORDER BY last_interaction_date DESC) AS recency_score,
  NTILE(5) OVER (ORDER BY interaction_count ASC)       AS frequency_score,
  NTILE(5) OVER (ORDER BY total_deal_value ASC)        AS monetary_score,
  /* segment label derived from R+F+M composite */,
  NOW()
FROM v_contact_rfm_base;
